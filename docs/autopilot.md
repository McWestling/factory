# Agent PR autopilot

Autopilot evaluates same-repo draft PRs into the default branch. It reads a ticket
identifier from the end of the title, such as `(ABC-123)`, then falls back to the
branch name. Forks and already-ready PRs are left alone, except that a new push
removes an old `ready-to-merge` label.

| Event | Evaluation |
| --- | --- |
| PR opened, synchronized, reopened, edited, labeled or unlabeled | Read the current head |
| Check run or suite completed; commit status completed | Read PRs on that head |
| Actions workflow completed (except autopilot itself) | Read PRs on that head |
| Autopilot's own status | Ignore |

The workflow-completion trigger is necessary because GitHub suppresses
[check events generated by Actions](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#check_run).

| `autopilot` status | Effect |
| --- | --- |
| pending: `waiting on: <names>` | Wait for missing or running checks, or unknown mergeability |
| success: `ready to merge` | Mark ready for review, add `ready-to-merge`, comment in Linear |
| failure: `needs fix: <checks>` | Keep draft; comment with log links and hand-back |
| failure: `needs fix: conflicts with main` | Keep draft; report the conflict |
| success: `skipped: no ticket id` | No promotion or Linear comment |
| success: `skipped: no-autopilot` | Opted out; remove the label to resume evaluation |

Wait-ons are `verifier` plus the optional list in `.factory/verifier.toml`:

```toml
[autopilot]
wait = ["deploy"]
```

The core validates this table and prints it as JSON with
`scripts/factory-verifier autopilot-config`. Autopilot reads trusted code and
config from the default branch. Check conclusions success, neutral and skipped
count as green; failures, cancellations and timeouts need fixes.

The workflow uses `GITHUB_TOKEN` with contents/checks read and
pull-requests/statuses write. It reads Actions secrets
`FACTORY_LINEAR_CLIENT_ID` and `FACTORY_LINEAR_CLIENT_SECRET`, exchanging them
for an app-actor token via Linear's client-credentials grant. Missing secrets or
an unknown ticket produce a warning; GitHub status and labels still work.
Comments dedupe by an exact marker line containing repo, PR, head, verdict and
sorted problems. Tokens remain in memory and are never logged.

Failure hand-backs say: merge latest `origin/main`, fix failures, commit,
run full `scripts/factory-verifier preflight` on the clean tree, then push.
[The full local push guard](https://linear.app/mcwestling/issue/DO-1398)
requires all local checks to pass on the pushed tree. Any later code change needs
evidence for its new tree. An unverified push requires explicit user authorization
and a non-empty `FACTORY_VERIFIER_OVERRIDE` reason.

Autopilot reads hosted results and mergeability, **not local evidence**. A pass
does not independently prove a full local run and does not guarantee freshness
after main advances. Unknown mergeability stays pending until another event.
There is no scan when main advances and no automatic merge.

Source and workflow ship in the setup skill's generated `verifier/` bundle.
Installation into consuming repos, secrets and ruleset setup are separate rollout
work. Install the script at `scripts/autopilot.mjs` and the workflow under
`.github/workflows/` when that rollout lands.
